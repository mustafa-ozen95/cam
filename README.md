# Camera panel (cam)

**English** · [Türkçe](README.tr.md)

Live view, playback and download for NVR/DVR/IP cameras; role/permission-based
membership, API keys, audit log. **Node.js 22+, no dependencies**, requires
ffmpeg. Interface in Turkish (default) / English.

| Type | Device | Protocol | Recording list |
|---|---|---|---|
| `uniview` | Uniview NVR (e.g. NVR302-32S) | LAPI (HTTP Digest) + RTSP, H.265 | per-day "has recording" → 15-min slices |
| `hikvision` | Hikvision NVR (e.g. DS-7616NI-Q2) | ISAPI (HTTP Digest) + RTSP, H.264 | real recording ranges → 15-min slices; camera registration on the NVR from the panel |
| `xiongmai` | Xiongmai / NetSurveillance DVR-NVR | DVR-IP (TCP 34567) | the device's file list |
| `kamera` | Single IP camera (Hikvision/Dahua/Uniview/custom RTSP) | RTSP | live only |

## Installation
`docker-compose.yml` follows the Compose standard (compose-spec.io). Settings come from the environment (`.env.example`).
Data lives in MariaDB (`db` service, named volume `cam_database`); to use an external database set `DB_HOST` and the credentials and
`VT_KOPYA=0` so the `db` service does not start. The HTTP port is not published; the reverse proxy in front provides the domain and TLS (it reaches the
panel on 80). The `/live` video comes from the `kamera-rtc` (mediamtx) service over 8189/udp; the server address given to the
browser is `KAMERA_RTC_ADRES`.
```
cp .env.example .env          # optional; chmod 600 .env
docker compose up -d --build  # or: npm start
cp docker-compose.override.example.yml docker-compose.override.yml   # without a proxy: panel directly on KAMERA_DIS_PORT (1165)
# second installation from the same source: separate folder + separate .env (KAMERA_KONTEYNER, KAMERA_RTC_KONTEYNER, KAMERA_DB_KONTEYNER, KAMERA_VERI_VOLUME, KAMERA_DB_VOLUME, KAMERA_RTC_PORT, KAMERA_CEREZ); data is not shared
npm test                      # unit + integration (fake device; needs a MariaDB, see "Database and backup")
node scripts/openapi.mjs      # regenerate the OpenAPI document from the routes
```
On first start `admin` is created (if `KAMERA_ADMIN_PAROLA` is not set, the password is in `veri/ilk-admin.txt`). Devices are added
from the **Cihaz** (device) tab (the connection is tested before saving); `KAMERA_CIHAZLAR` is only the initial seed while
the `devices` table is empty.

## Database and backup
All data (members, devices, roles, API keys, audit log, channel settings, /live layout, update status, KYM links) is in MariaDB/MySQL
(driver `mysql2`, utf8mb4). Connection: `DB_HOST` (default `db`), `DB_PORT` (3306), `DB_DATABASE` (`cam`), `DB_USERNAME` (`cam`),
`DB_PASSWORD` (required). At start the panel waits for the database (`DB_BEKLEME_SN`, default 60 s) and then runs its own migrations
(version table `migrations`, ordered, repeating does nothing). `/api/v1/saglik` is unhealthy when the database is unreachable.
- Tables: `users`, `devices`, `roles`, `builtin_role_permissions`, `api_keys`, `hub_links`, `audit_log` (one row per entry; the signature chain is kept and verified from the database), `settings` (name → JSON), `migrations`.
- The **secret key** is never stored in the database (a dump must not sit next to the encrypted device passwords): `KAMERA_GIZLI_ANAHTAR` (base64, 32 bytes; `openssl rand -base64 32`); if empty, `veri/gizli.anahtar` is used (generated with mode 0600 when missing). If the variable differs from that file, or from the key that filled the database, start-up stops with a clear message. Keep the key together with the backups.
- **Backup = a database dump** (e.g. `docker compose exec db sh -c 'mariadb-dump --single-transaction -u"$MARIADB_USER" -p"$MARIADB_PASSWORD" "$MARIADB_DATABASE"' > cam.sql`) plus the secret key.
- **One-time import**: at start, if all tables are empty and JSON-era files exist in `veri/` (kullanicilar.json, yetki.json, cihazlar.json, kanallar.json, gunluk.jsonl, merkez-baglari.json, guncelleme.json, live-duzen.json) they are imported in a single transaction; the audit chain is verified from the database and the row counts are compared with the files. Only if all of it matches are the files renamed to `<name>.aktarildi` (never deleted). Otherwise everything is rolled back, the files stay and start-up stops with the reason. If the tables are already filled and old files remain, nothing is touched and a warning is written. The import prints what it did (counts) to stdout.

## Permissions and API
- Permission catalog, DC roles (admin, network, teknik, muhasebe) and custom roles, camera **scope** (device/channel list), account expiry, IP/CIDR list.
- **API key** (`kp_…`, only the digest is stored, shown once; rate limit, concurrent streams, IP list, expiry, revoke, rotate).
- Privilege escalation is blocked: nobody can grant a permission/scope they do not have; nor can they touch an **existing** member (the password, role or deletion of a member more privileged than them or outside their scope), account constraints (expiry, IP list, rate/stream limit) cannot be handed on more loosely than one's own, and a person cannot lift their own restriction.
- An API key derives from its owner: if the owner is deleted / expires / is outside the IP list / loses access in KYM, the key stops working too, and its permissions never exceed the owner's **current** role; when a member is deleted their keys are revoked. A key without a member owner (integration-labelled, granted through yetki.yonet) works with its own rights. Ownership is determined by the `sahip` field, not by the key's display name.
- Camera scope is also enforced on write operations (channel settings, device edit/delete/clock); someone with a scope cannot add devices or delete recordings. `/api/bilgi` returns no channel/device data outside the scope. Channel numbers are PERMANENT (`cihazlar.json` · `ustSinir`): a deleted device's block is never given to a new device, so numeric channel scopes do not shift onto a new device.
- Documentation: `/dokuman/api-v1.tr.md`, `/dokuman/api-v1.en.md`, `/dokuman/openapi.json` (**requires a session**).

## Sign-in with the Identity Management Center (KYM)
The same flow as the DC panels (Authorization Code + PKCE): the user signs in on the center's page, the password never reaches this panel. A client is created in the center (Yönetim → Uygulamalar); the redirect address must be `https://<domain>/giris/merkez/geri`, and **which roles may enter is chosen in the center**. When all four variables are set, a "… ile giriş" (sign in with …) button appears on the sign-in page; local username + password sign-in always remains (so the panel stays reachable while the center is down).

```
KAMERA_KIMLIK_ADRES=https://dc.ornek.test          KAMERA_KIMLIK_ISTEMCI=<client id>
KAMERA_KIMLIK_SIR=<client secret>                   KAMERA_KIMLIK_DONUS=https://kamera.ornek.test/giris/merkez/geri
KAMERA_KIMLIK_BILDIRIM_SIR=<notification secret>    KAMERA_KIMLIK_AD="Kimlik Yönetim Merkezi"
KAMERA_KIMLIK_ROL_ESLEME='{}'                         KAMERA_KIMLIK_VARSAYILAN_ROL=           KAMERA_KIMLIK_DOGRULAMA_DAKIKA=5
```
- **Roles are the same as in the DC panels:** `admin` (everything, immutable), `network`, `teknik`, `muhasebe` (born without permissions; their permissions are granted under Yetki → Roller, name/identity fixed). A role in the center maps to the role of the same name; a different mapping via `ROL_ESLEME`, a role without a counterpart via `VARSAYILAN_ROL` (if empty, no account is created). Custom roles can be added too.
- On first sign-in, if the center says "an account may be created", a member is created (name from the local part of the e-mail, random password). The link lives in the `hub_links` table; it is bound to the member **itself, not to their name** (creation stamp, `uyeKimlik`): when the member is deleted the link is deleted, and a new member created with the same name cannot inherit the old identity. Old (unstamped) links are stamped onto the existing member at start-up; those without a member are dropped.
- Someone whose access is removed or whose role changes in the center changes here too: the center notifies immediately via `POST /api/kimlik/tazele` (HMAC signed); in addition `/api/kimlik-durumu` is asked every `DOGRULAMA_DAKIKA` minutes. If the center cannot be reached, the last known state remains in force.
- Behind a reverse proxy (Caddy/nginx) set `KAMERA_IP_BASLIGI=X-Real-IP`; cookies are then `Secure` and HSTS is on (turned off with `KAMERA_VEKIL=0`).

## Security
Only what the sign-in page needs is reachable without identity: the sign-in form, `css/js/font/simge`, `POST /api/giris|cikis`, the KYM sign-in flow and `/api/kimlik/tazele` (HMAC signed). **The API documentation (`/dokuman`) and `/api/v1` require a session**; `/api/v1/saglik` answers only from the container's own `127.0.0.1` address (HEALTHCHECK) and carries no details; `.json`/`.md` are never served from the static endpoint. The session cookie is bound to the member's creation stamp and session version: **signing out or changing the password invalidates all of that member's cookies**; signing purposes (session, KYM flow) are labelled separately. The per-IP sign-in limit (20 failures per minute → 60 s) is applied before the password hash is computed, and the hash is asynchronous; behind a reverse proxy without `KAMERA_IP_BASLIGI` this limit applies to the proxy's address. If a device's address/port changes, the password must be entered again (a stored password only goes to the target it was entered for).
Passwords use scrypt; device passwords AES-256-GCM; keys an HMAC digest; cookies HttpOnly+SameSite (Secure over HTTPS); CSRF header; CSP/nosniff/frame/referrer headers; 1 MB body limit; path traversal protection; brute-force lockout (sign-in and keys); no secrets in the log; HMAC-chained audit log. Behind a reverse proxy without `KAMERA_IP_BASLIGI` (e.g. `CF-Connecting-IP`), IP lists work on the socket address. Put TLS in front of plain HTTP.

## Update check
**Güncelleme** (update) in the top menu (`guncelleme.denetle` permission; admin has it) compares the running version with the **last successful image build** of the main branch on GitHub: how many commits behind, which commits are new. The direction is measured as well; if the running version is newer than the last build it is not called an "update". The check runs by itself every morning at 06:50, the button runs it immediately; if a new version exists, those with this permission see a warning at the top of the page. The screen **only looks**; updating is done on the server. Same rules as Settings → Güncelleme in the DC panels.
- The running version is written into the image at build time (`ARG SURUM` → `UYGULAMA_SURUMU`; the workflow provides the commit). When the build does not pass the commit it is read from `.git` in the build context (`docker/read-version.sh`; `.dockerignore` lets in only `HEAD` and the refs). The result is stored in the database (`settings`, `update-status`).
- The repository is public: no token is needed, GitHub is asked anonymously (limit: 60 requests per hour per IP). For a private repository `GUNCELLEME_JETONU` must be a read-only token (fine-grained, panel repositories only, Contents and Actions: read).
- If the panel cannot reach GitHub (closed network), the check says "erişilemedi" (unreachable).

## Language
Interface strings are written in Turkish; the dictionary and rules in `resources/views/web/js/lang.js` translate them to EN (the choice is made from the account menu in the top bar and stored in the browser). When adding a new string, add its English to the dictionary; write a rule (regex) for dynamic text. Role/permission names come from the server as `{tr, en}`.

## Design (identical to EYS)
The inner screens use the EYS panel's design template **unchanged**: top bar, account menu, column strip (live, recordings, three-pane device), admin tables, dialogs, notifications and theme are drawn with the same markup and the same CSS.
- `resources/views/web/css/eys/` and `resources/views/web/js/eys/` are **copies from EYS and are never edited by hand.** When EYS changes they are copied again with `node scripts/eys-sync.mjs <EYS checkout>` (`--kontrol` only reports the difference); file digests are in `css/eys/OZET.json`, and `test/eys-design.test.mjs` catches manual edits.
- `css/app.css` imports only `fonts.css` (local fonts), `eys/app.css` and `camera.css`.
- `css/camera.css` **only adds**: camera-specific parts (grid, player, timeline, recording row, full screen). It never redefines a selector defined by EYS (a test checks); if needed a new modifier such as `.detail--genis` is added.
- `js/split.js`: on narrow screens it drops into the right pane (the EYS `columns.js` rule, because the selection lives in page state, not in the address).
